

## Measurement batch 2: Equip/cFlocket.cpp (28 of 35 belonging targets exact incl. 11 compiler-made thunks; logic F33-F36, F39, F40 not attempted)
- **Reading the multiple-inheritance layout from the vtable blob.** The vtables of all subobjects sit consecutively in .rdata; scan words from the primary vptr to the end (py with `pe_reader`) and look for which table index holds which function address. A table starts where an adjustor thunk (`addi r3,r3,-N; b target`) for the next subobject begins. This gave the 11 vptr offsets (the ctor's stores give the same list), table lengths (primary vtable = 375 slots here) and which virtual lives in which table (F37/F38 are slots 8/9 of the table at +0x510).
- **A stand-in base chain reproduces the compiler-made thunks byte-exact.** Give each secondary subobject the right size and a virtual dtor (or RetClass/IsA/dtor where the thunk list shows them) and the compiler regenerates all 11 `??_E.../RetClass/IsA` adjustor thunks with the right mangled names (`WPA@` = -0xF0, `WEOA@` = -0x4E0 ...). The mangled thunk name encodes the offset, so it is a free layout check. Subobjects with no thunk in the list (0x420, 0x870) have no virtual dtor override.
- **RetClass/IsA thunks that jump to the 0x30 subobject.** The same base (cRegisteredClass-like: RetClass, IsA) appears three times (+0x30, +0x120, +0x510). The override's `this` is the FIRST such subobject, so thunks from the later tables subtract 0xF0 and 0x4E0 (0x120-0x30, 0x510-0x30). The bodies ignore `this`.
- **A function that lives only in a non-primary vtable is compiled with `this` = the subobject.** cFlocket::ReplicateInitialFields/ReplicateFields (table at +0x510) have NO separate thunk; the body uses `this+0x480` for the field at cFlocket+0x990. MSVC folds the adjustment into the function. Calling another member of the SAME subobject class (a `ReadVec3(...)` declared in that base) passes r31 untouched. Passing `this` to a free function taking the base pointer, or `static_cast<Base*>(this)`, emits `addi -0x510` plus a null check (`subfic/subfe/and`). So declare such helpers as members of the base subobject class.
- **Vec3 by value in a vector register.** `lvx128 v1` for a call argument means the parameter is `__vector4` (include `<ppcintrinsics.h>`). Source shape that gives the exact temp: `struct Vec3 { union { __vector4 v; struct { float x,y,z,w; }; }; Vec3(const Vec3 &o) : v(o.v) { x = o.x; w = 0.0f; y = o.y; z = o.z; } };` and the call `Begin(24, 96, Vec3(m_hint).v)` (whole-vector copy to a stack temp, then x, w=0, y, z stores, then reload into v1). A plain 4-float struct with a copy ctor is passed by hidden pointer; without a ctor, in a GPR pair.
- **Writing back three floats through the same pointer register.** `Vec3 *p = &m_hint; Vec3 v = *p; ...; p->x = v.x; p->y = v.y; p->z = v.z;` stores through the register that also held the lvx128 source (`addi r30,r31,0x480`); writing `m_hint.x = ...` re-derives `0x484(r31)`.
- **Member init order beats body order.** `Vec3` members with default ctors are zeroed in declaration order BEFORE the body. To get CD2's order (vec 0x970, float 0x980, vec 0x990, then pointer, then two floats) put the 0x980 float in the initializer list: `cFlocket() : m_fFlightTime(0.0f)`; the body sets the pointer and the two floats.
- **SpawnFromPrototype(proto, mem)** ignores proto: `if (pMem) return new (pMem) cFlocket(); return 0;` is `cmplwi; beq; mr r3,r4; b ctor` (success arm first). CD2's ctor takes NO arguments (RuffKing's takes the prototype).
- **The class registered with the factory is the PROTOTYPE.** MakeNew allocates 0x360 bytes and builds cFlocketPrototype; the registrar passes the object size 0x9B0. `RetClassName` (slot 11) returns "cFlocket".
- **Deleting dtors.** `virtual ~cFlocket();` defined empty in the .cpp gives F31 (calls F32) plus F32 (all 11 vptr stores, base dtor call). The in-class `{}` dtor of the prototype is inlined into its deleting dtor (F44), as in earlier files.
- **Float attribute read** needs `float mem = it->GetAs_float(); RwMemNative32(&mem, 4); field = mem;`; the string command passes the address of the data word (`GetAs_char_ptr()` defined inline) to a lookup. `switch (id) { case 0; case 1; case 2 }` reproduced F45's blt/beq/bge layout directly.
- **Open: F43 (prototype ctor) under LTCG.** The 14 float constants are loaded in CD2 through THREE base registers (`addi r8,r11,flt_820EB0B8@l` etc.): constants within 32 KB of one directly-loaded global are addressed relative to it (820F2444, 820EAA48, 820EB03C near 820EB0B8), further ones relative to 0x820F8C80 (r7) and 0x820F75DC (r4). The harness's LTCG model gives one pool base plus `lis` direct loads, so it cannot reproduce this; stores and values are otherwise the same as the target.
- **Harness trap:** under `--ltcg`, F28 (tail-calling SpawnFromPrototype) shows `0/6 words` although the plain build is EXACT; in the model the ctor is probably inlined. In CD2 it is not (F30 is standalone).
