
## cChaseBehaviour pilot findings (batch 2; F26 MakeNew, F79 registrar init, F80 atexit all exact, plain build)
- Split trap: this class's candidate window (0x824D1368-0x824D3FF0) is almost entirely OTHER classes: BreachPilot (F01-F25; F08 string "BreachPilot"), cChaseAndAttackPilotBehaviour (F27-F35), EquipmentDropBehaviour (F36+). Test: cChaseBehaviour is 0x100 bytes in CD2 (registrar size argument), so any function touching this+0x140.. (path pointers at 0x144/0x148, vector at 0x150) or vptrs at 0x100/0x108 belongs to a derived class. The class's own member functions (RetClassName 0x824CE570 etc.) lie before the window and have no targets.
- The registrar's MakeNew creates the PROTOTYPE (attribute handler), not the behaviour: `new cChaseBehaviourPrototype(packet)` = XCreateHeapBlock(0x90), out-of-line base ctor(packet) (NPCBehaviourPrototype), then only two vptr stores (0x00 and 0x18). A stand-in base with CAttributeHandler + a second polymorphic base (vptr 0x18, total 0x90) and `__forceinline` in-class derived ctor reproduced it exactly. Registrar size argument (0x100) is the behaviour's size, not the prototype's.
- RuffKing's `cChaseBehaviourPrototype` ctor stores vftables named after unrelated classes (ICF), so vtable names there are meaningless; only the store pattern matters.
- Harness: F42 (4-byte `blr` stub) got a false EXACT similarity pairing with the compiler-made prototype dtor; ignore.
- Hot-region vtable entries F72-F78 are shared base stubs (`*a3=0; *a4=0`, `*a2=0`, `this[18]!=0`, IsAlive-style flag test, VMX vec copy/return-constant) not defined by this file.

## cChaseBehaviour round 2 (real class code near 0x824CE570; 26 of 36 belonging functions exact)
- Split: the class owns F26..F57 (RetClassName, SpawnFromPrototype, RetClass, IsA, StaticCreateClass, ctor, behaviour/state functions, prototype HandleAttributes, member-pointer thunks) plus the registrar trio F79-F81. F01-F25 are the previous class (vtable 0x8210BA88); F58+ is cVehicleAttackedRockingBehaviour. F72-F78 are shared base stubs. The CD2 vtable has 121 slots: CAttributeHandler 0..10, 11 RetClassName, own virtuals at 68, 69, 74/75 (one function twice), 96, 100, 102, 104, 106-108, 111, 117, 118, then RetClass 119 and IsA 120 as the LAST slots. Slot numbers come from `lwz rX, N(vptr)` (N/4).
- Multiple inheritance with an out-of-line base ctor: the derived ctor stores every subobject vptr (0, 0x18, 0x1C, 0x30, 0x38) from the base chain alone; stand-in bases of the right size and polymorphism suffice. A Vec3 member with an inline default ctor plus a mem-initializer list for ALL fields in declaration order reproduced the ctor scheduling; body assignments did not.
- A handle that is tested and then passed: `m_hD0 = Ext(globalPtr, m_hD0)`. The decompiler hides the second argument; the early `lwz r4` is the tell.
- Struct-returning virtual: `Ext(reg, sub, sub->GetInfo(), id)` passes the hidden-return temporary directly (r5 = r3 from the call); a named local copy adds moves.
- Downcast idiom (sub-object pointer at +0x1C to the complete object): `static_cast<P*>(basePtr)` gives `cmplwi; addi -0x1C; bne; li 0`. `X *x = xs ? static_cast<X*>(xs) : 0; if (x) {...}` gives the jump-threaded `cmplwi; beq END; addi r31; cmplwi r31; beq END` of the target. `if (xs) { x = static_cast<X*>(xs); if (x) ... }` merges into `addic.` instead.
- A virtual returning `unsigned int` is tested with `cmplwi r3,0`, `int` with `cmpwi`, `bool` adds `clrlwi`: match the type to the compare.
- Pointers to virtual members (`&C::Slot112`) make the compiler emit 16-byte `vcall` thunks (F51-F57), named after the class that declares the slot.
- Constant pool trap (open): F37 and F38 load two float constants through a base register in CD2 (`addi r30, anchor`, `lfs f0, disp(r30)`, r30 saved in the prologue). The LTCG model does not produce the anchor for them; the plain diff of F37 otherwise matches. F38 is 99 percent plain and 97/98 words under LTCG. Functions with one constant (F31, F41, F44) load it directly and match.
- Open (F39, F40): CD2 computes `r10 = host + 0x7C` (address of an embedded link struct) right after loading the host and uses it for the second and later reads (`lwz r11, 0xC(r10)`), while the first read folds the displacement (`0x88(host)`). A local `HostLinks *links = &host->m_Links` in several arrangements never kept the address live. Control flow and casts otherwise match.
- Not attempted: F34 (event handler with an intrusive-list walk and a VMX store), F35 (intrusive-list front test), F47 (1008 bytes, function-local static table plus state lookup), F49/F50 (member-pointer delegate invokers).
- Tooling: work/ldiff.py Fnn symbol prints our LTCG words against the target words after a --ltcg run (--diff shows only the plain build).
