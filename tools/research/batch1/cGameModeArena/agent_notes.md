
## cGameModeArena findings (GameManagement/cGameModeArena.cpp; 9 of 12 belonging functions exact, HandleAttributes 95%)
- Split: the file holds cGameModeArena (deleting dtor F09 + its this-0x18 thunk F10, MakeNew F11, RetClassName F12, ctor F14, dtor F15, HandleAttributes F16, OnShutDownLevel F17), `cArenaLinker::GetArena` (F13, found by the string "cGameModeArena*"), two `GetRandSpawnPointInList<T>` instantiations (F18/F19, static-local cRandGen each) and the registrar pair F34/F35. F01-F08 are cCHordeArena (derived, 0x110 bytes, its own vtable 0x8215BD60), F20-F31 are barrier classes (cArenaBarrier, cCD1Barrier, cFinalMissionBarrier), F32/F33 shared return-0 stubs.
- Two-vtable classes: the thunk `addi r3,r3,-0x18; b <deleting dtor>` (F10) is generated by the compiler once the SECOND base (vptr at 0x18) has a virtual destructor as its first slot and the derived class overrides the destructor. Nothing extra to write. The second base here is RWS::CEventHandler in RuffKing (14 virtuals, 0x48 bytes incl. a short handle at +4).
- A constructor call that passes only `this` (`bl ctor` with r4 untouched) means the constructor takes NO packet argument even though MakeNew has one: `new cGameModeArena()`. Writing `cGameModeArena(const CAttributePacket &)` makes MakeNew pass r4 and spoils the match.
- Destructor prologue scheduling: `UnregisterGMM(int)` with the `short` member passed to an `int` parameter reproduces `lhz r10 ...; stw vptr 0(r3); extsh r3,r10; stw vptr 0x18; bl`. A `short` parameter loads straight into r3 and shifts everything.
- std::list sentinel node construction (inlined `_Buynode` body): `Node *n = Alloc(); if (n) n->next = n; Node **pp = &n->prev; if (pp) *pp = n;`. The second statement's `&n->prev` null test (`addic. r11,r3,4; beq`) is separate from the first `if (n)`. Writing both stores under one `if (n)` puts the addic. first; a single `Prev(n) = n` reference helper drops the test altogether.
- std::vector erase/clear as inlined by MSVC 2008: `if (first != last) { newLast = first + (end - last); if (end - last > 0) memmove_s(first, n*4, last, n*4); end = newLast; }` (memmove_s from <string.h>). `clear()` is `erase(begin, end)`, so the byte count is computed as (end - end) and tested with `srawi.`. Loops over `vec[2]` are `addic. r,-1; bne` loops with stride 0x10.
- Vector destructor body (`if (first) free(first); first = last = end = 0;`) inlined into the owner's destructor with `operator delete(p)`; destruction order is reverse declaration order, arrays last-to-first.
- Stack slot order of locals follows SIZE ascending (smaller locals nearer sp), ties by first appearance, not by declaration order. GetArena (F13): `cEventId id` (16) at 0x50, `cMsg msg` at 0x60 and the hidden-return `cString` temporary at 0x80 only appeared once cMsg was made smaller than the string (0x18 vs 0x1C bytes). Sizes of unknown structs can be fitted this way.
- `std::string::c_str()`: write `m_nRes >= 16 ? ptr : buf` (the `blt` jumps over the `lwz r4,4(r3); b` ptr arm to the `addi r4,r3,4` buf arm). The reverse ternary swaps the arms.
- Inlined `SendMsg`: `if (msg.pTarget != g_NullTarget && *msg.pTarget != 0) Dispatch(msg);` with `g_NullTarget` a global pointer variable (CD2 0x83821310).
- GUID temporaries in HandleAttributes: `RWSGUID g = GetListGUID(list, i); void *p = FindEntity(g);` (named local in the caller plus the static inline wrapper that copies) puts the callee's hidden-return temp at the LOWER slot (0x60) and the wrapper's copy at 0x70, matching the target. `void *p = FindEntity(GetListGUID(...))` swaps the two slots.
- `container.push_back(p)` taking `T *const &` forces p into a stack slot; the target then reloads p from the slot after the call (`lwz r3,var_80(r1)`) for the virtual call. The store of p happens before the null test.
- Signed vs unsigned compares: `cmpwi` against a byte-swapped value needs `(int)rwSwap32(x) == 1`; a plain unsigned compare gives `cmplwi`.
- String-id hash loop (inlined `cLocStringManager::GetStringID`): `int mult = chain; int id = 0; for (char c = *s; c != 0; c = *++s) id = id * mult + c;` with the multiplier declared BEFORE `id`; the signed char test gives `extsb; cmpwi`. Writing the chain load inside the loop expression gives the wrong `mullw` operand order.
- Switch with 11 cases (0..10) compiled as an inline jump table in .text (11 data words at function+0x78 right after the `bctr`). The harness listing hides those words on the target side only, so `--diff` output is misaligned by 11 words below the `bctr`. Compare words with a side-by-side script instead (work/cmp.py). Case bodies are laid out in source order (case 7 before case 6 in the target).
- Unresolved in HandleAttributes: the address-taken `void *p` of case 0 lives at 0x54, the target keeps it in the SAME slot as the float `mem` of cases 3/4 (0x50). Moving p's declaration (function scope, case scope, loop scope) did not merge them.
- Unresolved in GetRandSpawnPointInList: the target tests the size with `srawi. r8,r10,2; beq` and then recomputes the size for the Rand argument. Source forms using the size only for the test get folded into `clrrwi; cmpwi; beq` (a `(x>>2) != 0` test becomes a mask), while a size kept in a local `n` and reused gives `srawi.` but no recompute. Layout `if (n) return list[Rand(..)]; return 0;` (zero-return arm last) is right. cRandGen inline: ctor stores the seed to +0 and +4, Rand does `+4 = 0; state = state*0x41C64E6D + 0x3039; return ((state >> 16) & 0x7FFF) % max;` (`divwu` plus `twllei` zero trap).
- Registrar initializer F34: the harness target is only 15 words (the extraction stops after `bl atexit`, no epilogue). All 15 words match ours apart from relocations, so it is reported as 78.9% because ours has the 4 epilogue words.
