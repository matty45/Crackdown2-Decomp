
## cAmbientVFXSpawner findings (VFX/cAmbientVFXSpawner.cpp; F03-F11, F14, F19-F21, F33 exact; F13 and F32 effectively exact)
- Split: this file = cAmbientVFXPrototypeBase RetClassName + scalar deleting dtor (F03/F04), cAmbientVFXPrototype MakeNew/RetClassName/dtor (F05-F07), cAmbientVFXSpawner RetClass/IsA/StaticCreateClass/MakeNew/HandleAttributes/virtuals/CalcRand* (F08-F21), registrar init + atexit (F32/F33). F01/F02 and F22-F31 are other classes' code (PrototypeBase::MakeNew F22, PrototypeBase::HandleAttributes F25, SpawnerBase RetClass/IsA/update/Spawn/Release F23/F24/F26-F31).
- IDA truncates functions that end in a call it believes never returns: F32 (ends at `bl atexit`) and F13 (ends at the tail `b CalcRandInitSpawnTime`) lack the trailing epilogue/`blr` in the target slice, so the harness shows a few "missing" words. Check the gap to the next function first (F13 is 0x18 bytes before F14, i.e. 6 insns). They are effectively exact.
- Chained inline constructors (CAttributeHandler -> PrototypeBase -> Prototype with embedded GUID handler) need `__forceinline` on both in-class ctors to be inlined into MakeNew under /Ob1. The Spawner's plain in-class ctor was inlined without it.
- `bool r = a || b; return r;` gives `li r11,0 / bne / li r11,1 / clrlwi r3,r11,24` (target F09). `unsigned char b = a || b; return b != 0;` adds `clrlwi r11; addic; subfe` (target F27/F18). Plain if/else or early returns fold into `beqlr` + `li r3,1` and never match.
- Float range branches: `if (start < end) { if (p < start || p > end) fail } else if (p > end && p < start) fail` reproduces CanSpawn's layout; writing the `>=` arm first inverts it.
- `if (Base::ReleaseVFX()) { ...; return true; } return false;` (success arm first) matches; `if (!Base::ReleaseVFX()) return false;` does not.
- In-class virtuals called qualified (`Base::OnVFXFinished()`) are inlined: OnVFXFinished becomes a virtual call to ReleaseVFX (slot 9).
- Static local class pointer: `static cClass *p = new cClass(id, name, size); return *p;` reproduces the guard + XCreateHeapBlock(0x5C) + out-of-line cClass ctor exactly.
- Rand: `m_nSeed = 0; m_nNext = m_nNext * 1103515245 + 12345; return (m_nNext >> 16) & 0x7FFF;` inline; time = RetGameTime() - (unsigned)(f * -1000.0f).
- Unresolved F15-F17 (CalcRand*): same instructions but the target loads its two float constants through a shared base register (`addi r30, anchor`, displacements 0x84/0x3D4, r30 saved in the prologue). Ours loads each constant with its own lis. Tried unsigned/int/double/divide variants offline: no anchor appears.
- Unresolved F12 HandleAttributes: target has three 16-byte GUID slots (return buffer, a 4-load/4-store copy, then a second interleaved copy passed by pointer). Every arrangement tried (one or two nested `RWSGUID g = id` wrappers, explicit temp copy, named local in the caller) leaves two slots; by-value RWSGUID is passed in r3/r4 here (POD), so it is not a by-value argument.
- Unresolved F18 (and F27): one word differs; the target tests bit 12 with `extrwi r10,r11,1,19`, we always get `rlwinm r10,r11,0,19,19` (mask 0x1000), also for `(x>>12)&1` and a bitfield.
